CRITICAL PASSWORD SECURITY & CRYPTOGRAPHY MATRIX

Fundamental cryptographic principles for cybersecurity engineers, penetration testers, and defense architects.

1. Hashing is Not Encryption

Hashing is an irreversible one-way mathematical trapdoor function. There is mathematically no decryption key or reverse operation. Encryption is two-way (ciphertext decrypted via secret keys). Never confuse cryptographic digests (data integrity and credential verification) with reversible encryption (confidentiality).

2. Fast Hashes ≠ Secure Password Storage

General-purpose algorithms like SHA-256, SHA-384, and SHA-512 were engineered for high throughput on data streams. Modern consumer GPUs compute billions of SHA-256 hashes per second. Storing user passwords as bare SHA-256 makes them trivial to break via dictionary attacks, Hashcat, or rainbow tables if leaked.

3. Dedicated Storage: Argon2id

For storing user passwords in real web backends, use an adaptive, memory-hard key-derivation function. Argon2id (RFC 9106) is the gold standard winner of the Password Hashing Competition, designed to defeat ASIC and GPU parallel cracking. Secondary alternatives include scrypt or properly tuned bcrypt (work factor ≥ 12).

4. Cryptographic Salts are Mandatory

A salt is a unique, cryptographically random sequence of bytes (e.g. 16+ bytes from a CSPRNG like crypto.getRandomValues) generated per account. Salts ensure two identical passwords produce completely distinct hashes, destroying precomputed Rainbow Table attacks. Salts are public and stored alongside the hash.

5. Not a Complete Auth Subsystem

A client-side hash generator cannot substitute for enterprise authentication. Production architectures mandate: TLS/HTTPS transport, server-side parameter re-validation, rate-limiting against automated brute force, multi-factor authentication (MFA/FIDO2 WebAuthn), and secure HTTP-only SameSite cookies.

6. Client-Side Threat Model & Boundaries

Local computation eliminates network transmission, shielding against Wi-Fi sniffers and intermediary proxies. However, client execution cannot protect against a compromised operating system, malicious browser extensions, hardware keyloggers, or Cross-Site Scripting (XSS).
